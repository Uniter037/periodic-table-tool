# 排错日志与开关

状态：设计，待实现。对应OPS-02，工作包A12。当前EXE不因本文创建而获得这些功能。

## 1. 界面与设置

入口：“设置 → 日志与排错”；快捷入口：“帮助 → 查看日志”。错误提示提供“查看相关日志”和“复制错误摘要”，按error_id定位。

| 设置 | 默认 | 行为 |
|---|---|---|
| 记录日志 | 开 | 总开关，关闭后停止新的持久化诊断记录 |
| 详细程度 | 标准INFO | 精简WARNING、标准INFO、详细DEBUG |
| 临时详细排错 | 关 | 一键开启DEBUG，30分钟或退出时结束，可提前结束 |
| 记录性能信息 | 关 | 记录导入、转换、绘图、队列等待、发布耗时 |
| 下次启动详细排错 | 关 | 一次性标志，bootstrap读取后清除，用于启动问题 |
| 保留天数 | 7天 | 可选1/7/30天 |
| 总空间上限 | 20MB | 可选10/20/50MB，单文件2MB轮转 |

总开关最高优先级。关闭时结束临时调试、拒绝新记录、丢弃未写队列并关闭句柄；已经开始的一次写入可完成，之后不再写。已有日志保留，另有“清空历史日志”。级别和开关即时生效并持久化，无需重启。

临时调试结束恢复开启前的级别和开关；期间用户主动改设置，以最新手动设置为准。原先关闭时点击临时调试明确显示“临时开启日志”，到期恢复关闭。临时会话不跨重启恢复。性能记录默认仅本次会话有效。

关闭日志不关闭错误提示、任务进度、自动草稿或导出恢复journal；它们是工作恢复所需数据，设置页须解释。“清空历史日志”不能删除这些文件以及项目、预设和图片。

## 2. 查看器和诊断包

日志查看器支持级别、模块、时间、job_id/error_id过滤，关键词搜索、暂停自动滚动、复制选中内容。默认最近1000条，游标分页，不把全部文件加载进Tk。中文摘要可展开结构化字段和堆栈。

按钮：打开日志文件夹、导出诊断ZIP、清空历史日志。清空显示范围并协调writer，跳过其他运行实例的活跃文件；删除失败逐项说明。导出自动改名，不覆盖旧包，不自动上传。

诊断包默认含所选时间段脱敏日志、应用/构建/OS/Python/依赖版本、显示缩放、渲染后端、实际字体、诊断设置和文件清单。导出前显示包含项。默认不含Excel、项目数据、元素数值、标注正文、剪贴板、用户名、源绝对路径或环境变量全集。

可选附加绘图配置时列出字段，排除数据和自定义标题文字。需要复现数据时由用户另行主动选择附件，不能随DEBUG自动收集。日志和配置中的异常message、路径必须脱敏，不仅过滤结构化字段。

## 3. 记录范围

| 模块 | INFO | WARNING/ERROR | DEBUG（仍脱敏） |
|---|---|---|---|
| 启动 | 版本、初始化阶段、结束 | 缺依赖、配置/资源失败 | 阶段耗时、适配器选择 |
| 导入 | 读取器、区域大小、组数、诊断数量 | 解析、重复元素、缓存缺失 | 映射类型、转换步骤、校验分支 |
| 状态 | 命令类型、revision、变更数量 | 提交拒绝、冲突、无效引用 | 事务阶段、撤销合并理由 |
| 绘图 | 任务开始结束、style_id、画幅 | 字体回退、范围错误、worker崩溃 | 计划hash、旧消息丢弃原因 |
| 输出 | 格式、尺寸、发布状态 | 无权限、写入失败、恢复失败 | 暂存/发布/journal阶段 |
| 项目 | 保存/加载/迁移版本、恢复结果 | 损坏、迁移/原子保存失败 | 校验阶段、草稿revision |
| UI | 已提交命令 | 回调异常 | 布局切换；不逐键记录正文 |

异常在拥有处理职责的边界记录一次，上层转发error_id，避免重复堆栈。同类警告限频并记录抑制数量；进度按阶段或节流周期记录，不逐单元格、逐像素、逐鼠标移动记录。

## 4. 格式与接口

采用标准logging与UTF-8 JSONL，一行一事件。字段：schema_version、timestamp_utc、monotonic_ms、level、event_code、message、session_id、process_role、module、trace_id、job_id、item_id、request_id、project_revision、error_id、duration_ms、details。无关字段省略，event_code稳定，文案可本地化。

trace_id贯穿一次用户动作及子任务；通过revision/data_hash关联读取和绘图。error_id展示给用户。堆栈保留函数/行号，路径替换为<APP>、<USER>、<SOURCE:id>；不捕获局部变量。

DiagnosticService契约由A00冻结：configure(settings)、start_session(duration_minutes)、stop_session()、query(filters,cursor)→LogPage、export_bundle(selection,directory)→Path、clear_history()→ClearResult。domain不依赖logging；应用和适配器在边界记录；UI仅调用服务。A12实现infrastructure/diagnostics和ui/diagnostics。

## 5. 并发和故障降级

主进程QueueListener为单writer，worker通过有界QueueHandler发送脱敏事件；禁止多个进程共享RotatingFileHandler写同一文件。每个EXE实例独立session目录。bootstrap早期使用轻量日志，正式writer接管避免重复；日志开关在加载业务模块前读取。

建议队列上限2000事件，单事件32KB，堆栈100帧。队列满优先丢DEBUG/INFO；WARNING/ERROR非阻塞尝试，失败进入有界内存错误缓冲并计数，恢复后汇总丢失数量。不得阻塞UI或绘图等待日志。

目录为user_directory()/logs。按总容量和天数清理最旧已关闭文件；活跃文件达到2MB轮转。磁盘满、无权限、writer失败只给一次非阻塞提示，停止磁盘写入并保留有界内存状态；不能递归写日志或让绘图失败。关闭总开关时不写替代stderr文件。

捕获主线程、Tk report_callback_exception、线程异常、worker退出和IPC错误，保留原业务失败语义。无控制台EXE仍提供启动错误对话框、error_id和可得的日志位置。强制终止/底层崩溃不保证完整堆栈，只报告实际获得的退出码和最后阶段。

退出flush等待≤1秒，不无限阻塞。清理仅操作已验证logs根目录和应用生成文件，不跟随越界符号链接。导出恢复journal不在该目录，不受日志开关或清理影响。

## 6. 验收

| ID | 场景 | 预期 |
|---|---|---|
| LOG-T01 | 关闭后继续导入/绘图/导出并触发错误 | 无新增诊断写入，错误提示与恢复journal正常 |
| LOG-T02 | 改级别、临时调试到期、退出、期间手动改设置 | 按§1恢复，不意外永久DEBUG |
| LOG-T03 | 导入→命令→worker→输出故障 | trace/job/error_id可串起问题，不重复堆栈 |
| LOG-T04 | 容量/期限达到、两个EXE同时运行 | 正确轮转，活跃文件不误删 |
| LOG-T05 | 无权限、磁盘满、队列满、writer异常 | 业务可用、可见丢失状态、无递归异常 |
| LOG-T06 | 异常含用户名/绝对路径/单元格正文 | 日志与ZIP均脱敏，DEBUG不泄露原始数据 |
| LOG-T07 | 清理和导出诊断ZIP | 不动项目/图片/journal，不覆盖旧包 |
| LOG-T08 | 冻结EXE启动错误、Tk回调、worker退出 | 无控制台仍能定位问题，早期日志可读取 |
| LOG-T09 | 连续更新、1000+条筛选、快速切换开关 | UI有界响应，关闭语义一致 |

LOG-T01/T03/T05/T06/T08纳入M1，其余M2完成；M3验证实际发行EXE。日志不是开发末期添加的散落print，而是模块接入时必须遵守的公共协议。
