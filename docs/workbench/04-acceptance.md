# 验收、性能与发布标准

## 1. 验收原则

本文件所有数值为目标或样例预期，不代表本轮已经运行测试。验收必须记录操作系统、Python/依赖版本、硬件、字体、显示缩放、提交SHA、输入hash与输出位置。已有v1.6.0测试保留，不能以新测试替换历史一致性测试。

测试层次：领域规则单元测试→端口契约测试→读取/持久化/渲染集成→UI交互→冻结EXE端到端。对错误路径、数据语义和并发写真实测试；不写仅验证getter返回常量的低价值测试。

前三表ROUND辅助区分别含128、160、160个公式；当时缓存均存在。Distortion为B28:AG31，对应第3—6行；Shuffle与DeltaE为B27:AG31，对应第2—6行。它们不应被当作第二批实验数据。说明“保留四位小数”仅作为显示候选，不能擅自舍入源值。

`R最低位点及占位倾向`：A21:AF21为32个元素，A24:AF24为完整位点文字，A22:AF22和A23:AF23分别是稀疏分组。上方B1为换Ti、B10为换Ni；A2:F5、A11:F15为按位点分组的元素名单。分组展开和横向属性两种导入应得到相同对应关系，不重复创建元素。

### GOLD-01 完整任务

1. 导入三个数值工作表，确认15组、480个有限数值，来源地址可追溯。
2. 关联32个元素的位点属性；列顺序打乱的合成副本结果应相同。
3. 各指标统一色标，先选择线性，再显式设置参考中心验证双斜率；两种模式不得混淆。
4. 原始数值着色，四位小数显示；检查0比例组常量数据不导致崩溃。
5. 导出15张PNG及至少一个SVG/PDF，命名可区分指标和比例，旧同名文件保持hash不变。
6. 保存项目、关闭、源文件暂不可用时重开，预览与再次导出保持一致。
7. 编辑某元素文字/位置、撤销/重做；修改源数据后重新读取并处理冲突。
8. 检查无额外空图片、无辅助区混入、无负号丢失、无类别被转换为数值。

## 4. 成图质量标准

日志需求OPS-02追加[日志验收LOG-T01—LOG-T09](05-diagnostics.md)，依照其M1/M2/M3分级执行，最终报告不得漏项。

固定环境做原脚本像素对照；跨机器字体差异不能承诺逐像素一致。记录实际使用字体，缺字必须可见提示并采用可用回退。不得通过改变基准图来掩盖未解释的差异。

科学模式：布局、色彩归一化、标注值、图例类别先做结构断言；固定字体下渲染快照做视觉回归。PNG尺寸等于CanvasSpec×DPI，除明确legacy_tight裁切外不变。SVG/PDF检查可解析、页框/视框正确、主要图形保留矢量，不以PNG嵌入冒充全矢量输出。

预览与输出的“所见即所得”指数据、颜色映射、物理布局、标注位置、画幅和裁切一致，不要求不同DPI抗锯齿像素完全相同。自动换行在统一物理布局阶段决定，不能因预览DPI降低而重新改变断行。

人工检查长中文、多行、负号、科学计数、大字号、透明背景、图外刻度、边界标注和小窗口。高自由度允许用户有意重叠/越界，程序提示但不擅自移动，导出前可查看警告。

## 5. 性能预算（须实测，不是已实现承诺）

参考机器：Windows x64、4核、16GB内存、SSD；报告CPU型号和字体环境。冷启动与热启动分开，至少5次，交互延迟用至少20次样本报告P50/P95。

| 场景 | 目标 |
|---|---|
| 点击/输入主线程反馈 | P95 <100ms，不等待渲染完成 |
| 32元素×5组×3表的小文件导入预览 | 热态≤2s；冷态单独记录 |
| 1600px以内普通预览 | 热态P95≤1.5s，包含防抖另行注明 |
| 连续修改 | 不积压20份预览，不显示迟到结果 |
| 导入100万单元格选区 | 可取消、分块进度、UI响应；记录时间和峰值内存 |
| 源码/EXE启动 | 分别记录；EXE冷启动目标≤10s，不将解压时间隐藏 |
| 取消 | UI≤100ms反馈；后台终止/清理目标≤2s，超时显示清理状态 |

导出内存估算按像素面积×至少16字节工作预算，加渲染基础内存；超预算时建议降低DPI/画幅或串行处理，不能直接尝试直至系统失去响应。统一默认最多1个导出worker；独立预览worker启用前验证总峰值。

## 6. 迁移、发布与交付门禁

现有入口可复用：`python -m pytest -q`、`python build_exe.py`、`python make_dist.py`、`python verify_exe.py --report output/exe-acceptance.json`。实施者先核对当前脚本参数；本文件不保证未来脚本参数不变。

发布前必须：

1. 所有P0/P1需求有通过证据，S0/S1为0；相关S2修复完成。没有测试环境的项目标记not-run，不写pass。
2. 旧一致性、项目、作业、布局、发行包测试通过；真实Excel验收通过；源码启动与冻结EXE都跑实际渲染。
3. 构建在锁定环境进行，依赖清单与构建脚本一致。增加Excel依赖后验证隐藏导入与资源，不仅检查EXE文件存在。
4. EXE、Windows ZIP、源码ZIP、SHA256SUMS、发布说明齐全；版本在应用、项目元数据、包配置和文档一致。
5. 源码ZIP/wheel包含新domain/application/infrastructure包；仅允许合成xlsx模板进入examples；排除用户原表、临时目录、日志、个人预设和凭据。
6. 用干净目录验证“下载→解压/运行→导入→预览→导出”；安装目录不可写时仍能保存配置并选择输出目录。
7. 发布说明列出新增功能、兼容模式、项目迁移、已知限制和必要恢复方法；不得宣称支持未实现的xls或公式计算。
8. 若本轮获授权发布，再上传GitHub发行资产，核对远端版本、大小、hash及latest状态；否则只交付本地可审查产物。
