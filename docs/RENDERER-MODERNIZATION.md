# 绘图内核去历史包袱：2.0 重构边界与任务书

状态：2026-11-18 已实现独立内核、Agent v2、显式项目迁移及原生桌面；源码默认入口已切换，旧运行内核暂留作兼容回归，未发布新版 EXE。

## 1. 产品决策

从“复现原脚本”转向“独立的科学绘图工作台”。新内核不承诺与原脚本逐像素一致，不继续复现错误范围、零值隐藏和受脚本限制的编辑能力。保留用户数据、有效绘图参数、标注编辑能力和高质量输出；发生语义变化必须给出迁移报告。

不能把删掉测试参考文件等同于完成重构，也不能仅删除一致性测试后宣布成图正确。当前未提交的 UI、DPI 修复属于独立改动，进入实施前先单独保存代码基线；不要混入历史引擎清理提交。

## 2. 已核实的技术债

| 位置 | 当前问题 | 目标 |
| --- | --- | --- |
| `tests/fixtures/originals/` | 12 个原始脚本是测试资产，不是运行入口 | 退出主线验收和发行包；历史 Git 标签保留证据 |
| `core/styles.py:STYLES` | 14 个模式含脚本文件名、实验特定范围及历史行为开关 | 普通、可编辑、可保存的外观预设，不控制引擎分支 |
| `core/styles.py:render_table` | `custom/corrected` 决定验证、字体、显示、色条和数据处理，单函数负担过重 | 一个参数模型、一条渲染路径，按职责拆分 |
| `core/scientific.py:corrected_style` | 科学规则是对旧样式做修补，包含按样式 ID 特判 | 科学规则是默认契约，不需要“修正模式” |
| `core/options.py:apply_custom_params` | 中文 UI 文案、文本参数和兼容语义混合 | GUI 文案只留在 UI；业务层接受稳定枚举和数值 |
| `core/ptable.py:build_elements` | 缺失值填 0；几何、数据和 tuple 标记块混合；错误锕系文字靠渲染器修补 | 纯几何布局；元素格与说明标记独立；缺失与零值严格区分 |
| `application/project_codec.py` | 默认值与解析先依赖旧 STYLES，再覆写；兼容模式下候选参数可能不实际生效 | 新模型直接验证；旧字段只在迁移入口处理 |
| `main.py` | 原脚本兼容开关、脚本来源文字、按模式保存编辑状态；负责大量业务协调 | 工作区编辑当前文档；控制器调用应用服务 |
| `application/agent_api.py` | 对外暴露 `mode_id/compatibility` 等旧字段 | 版本化接口与能力声明，新请求面向绘图配置 |
| `tests/test_consistency.py`, `tests/verify.py`, `tests/test_dist.py` | 原脚本逐像素一致、分发数量是硬性要求 | 科学正确性、迁移无损、交互与图像质量构成新验收 |

并非名称含 legacy 的代码都应删除：`excel_import.legacy_data` 是数据适配器，旧用户配置搬迁是数据保护。分别核实调用契约后再改名或替换。

## 3. 必须保留的能力

- 热力图与文本标注；两种现有元素布局；118 元素正确编号及镧锕说明。
- 自定义颜色节点、线性/中心分段归一化、自动与固定范围、空值外观。
- 色条开关、独立刻度/标签及隐藏项、方向、位置、比例、精确框、隐藏后保留空间。
- 元素符号/原子序数/数值独立字号与显示；文本换行、单位、逐元素偏移和显示/着色/参与自动范围开关。
- 固定物理画幅、主图区边距、透明背景、紧裁切、PNG/SVG/PDF、高 DPI 输出及字体回退。
- Excel 导入与多数据组、共用色标批量导出、项目与预设、撤销、草稿、日志、取消任务和防覆盖命名。
- GUI 与 Agent 共用同一渲染服务；图形点击命中、拖动、排版诊断、样图对照。

色图预览器作为独立辅助工具保留，不占用“周期表绘图模式”。线性与中心分段的科学语义必须独立配置，不再由旧样式 ID 隐含决定。新的归一化类型不属于本轮必需范围。

折叠布局隐藏镧系/锕系元素时，应明确提示其中有多少个已输入值未展示；新项目默认使用完整展开布局。范围外颜色可作为明确配置保留，不能恢复“把零值当作空值”的旧判断。若支持多种舍入政策，应以算法语义命名，不再绑定兼容身份。

## 4. 最小目标架构

沿用已有 Python、Tkinter、Matplotlib、domain/application/infrastructure 分层，不增加 Web 前端、微服务或通用插件框架。

```text
GUI 文本/控件 ─┐
Agent v2 JSON ─┼─> application 绘图用例 ─> PlotSpec 校验 ─> 渲染器 ─> 输出服务
旧项目迁移 ───┘                              │              └─> 图元索引/诊断
                                         几何布局
```

| 模块（拟新增） | 唯一职责 | 禁止依赖 |
| --- | --- | --- |
| `domain/plot_spec.py` | 版本化配置：LayoutSpec、ColorScaleSpec、ColorbarSpec、TextSpec、FigureSpec、ElementOverride；类型与范围约束 | Tk、Matplotlib、脚本 ID |
| `domain/layout.py` | 根据布局规格生成元素格与说明标记，不读取数值 | GUI、文件 I/O |
| `application/plot_service.py` | 解析当前数据组、验证、调用渲染、返回结构化结果 | Tk 控件 |
| `application/project_migrations.py` | schema 1 到 schema 2 转换、差异报告；保存前不写源文件 | GUI；新渲染器不能反向依赖它 |
| `infrastructure/rendering/` | Matplotlib 后端：renderer、colorbar、text、export；只消费规范化配置 | STYLES、compatibility、中文 UI 值 |
| `ui/plot_controller.py` | 控件文本与领域值转换、错误定位、调度预览 | 旧脚本规则 |
| `resources/presets/` | 版本化 JSON 预设：配置初始值和说明 | Python 渲染逻辑 |

避免把内部 Figure/Artist/Tk 对象存进项目或发给 Agent。渲染结果继续提供稳定的元素/文字角色索引，供当前命中、拖动和诊断复用。移动函数必须同步修复测试及打包模块发现。

## 5. 项目与预设迁移

1. 新项目显式 `schema=2`，保存完整绘图配置及数据快照；预设名只作来源说明，渲染不依赖预设仍然存在。
2. schema 1 只在加载/迁移边界识别，按其真实生效配置解析；不能简单把 `compatibility=true` 改为 false。
3. 遍历 `current` 和所有 `styles` 编辑状态，保留各状态数据、Excel 组及组编辑、单元素覆盖和扩展字段；不能只迁移当前页。旧状态转为有名称的文档变体，不直接丢弃。
4. 保留用户显式输入的范围和刻度；发现异常给出提示，不能“智能纠正”真实实验参数。旧兼容模式中未生效的字段不能突然启用，迁移报告需指出取舍。
5. 历史缺陷（零值当空值、锕系错误文字等）按新规则处理，逐项列出影响；旧舍入选择需明确转换策略，不能无提示改变显示精度。
6. 生成新文件，默认名称带 `-migrated`，不覆盖源 `.ptproj`。返回源 schema、目标 schema、changed_fields、warnings、unsupported_fields；未知必需语义阻止迁移，不猜测。
7. 迁移可重复执行且结果确定；保留来源指纹，不记录私人数据到公开测试资产。旧项目的原始数值及 `001/1.00/1e3` 文本格式必须保留。
8. 对必须复现历史图的用户保留旧发行版下载说明，避免在新渲染内核永久携带另一套规则。

迁移必须按新 schema 显式构造，禁止整体复制旧样式字典后修补：当前空白 `margins/cbar_box` 可能留下继承值，旧 `cbar` 和高亮键也可能意外生效。需要逐字段确认实际行为后再转换。新布局 API 对非法名称必须统一拒绝，不能把未知值默认为折叠布局。

## 6. GUI 与 Agent 边界

- GUI 主入口改为“图表类型、布局、预设”，移除脚本名称与原脚本兼容开关。每个预设都能编辑全部适用参数。
- 预设默认只应用外观，不替换数据；应用前后数据组及逐元素编辑行为须有明确规则与测试。
- Agent v2 提供 schema/capabilities、规范化配置、错误字段路径和迁移操作。沿用 revision 并发检查、原子保存和可取消任务。
- 旧请求通过单独适配层显式转换，或返回结构化迁移提示；不偷偷改写旧请求的输出语义。新 `describe` 不宣称支持旧兼容绘图。
- GUI 与 Agent 相同配置产生相同绘图配置指纹及图元，不要求图片文件时间戳等元数据相同。

## 8. 新验收标准与删除条件

- 科学语义：零值、缺失、负数、常量组、范围外值、NaN/Infinity、118 元素与正确镧锕范围。
- 迁移：全部旧模式、两种兼容状态、缺省/显式参数、多个样式状态、Excel 编辑和覆盖字段；失败不写文件。
- 颜色条：端点及任意中间值、标签隐藏、水平/垂直、显式框、保留空间、自动范围及批量共用范围。
- 图像质量：固定字体/依赖环境的 SVG 图元与几何断言，加 PNG 容差比较及代表图人工检查；不以旧脚本像素作为唯一正确答案。
- 交互：预览与导出位置一致、缩放后命中准确、标注拖动/撤销正确、大小窗口和高 DPI 可用。
- 数据安全：不覆盖原项目、自动命名不冲突、取消不发布半成品、revision 检查继续生效。
- 分发：源码包、隔离安装、冻结 EXE、Agent 调用均通过；依赖和资源齐全，排除私人样例。

只有替代验收覆盖相应行为、迁移器落地且新入口可用后，才移除旧逐像素测试及参考文件。收尾时删除临时双引擎开关和旧渲染入口；迁移适配器可以保留，因为它只负责读取用户资产，不左右新内核行为。
